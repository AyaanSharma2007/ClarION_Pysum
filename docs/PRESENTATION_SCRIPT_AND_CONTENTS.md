### Slide 7: Enterprise Hybrid Architecture (pgvector + Neo4j)
- **Category:** System Architecture
- **Headline:** Under the Hood: Enterprise Hybrid Architecture
- **Subtitle:** Leveraging the exact strengths of pgvector and Neo4j via the Retrieve-Then-Enrich pattern.
- **Left Panel (Dual-Database Division of Labor):**
  - *PostgreSQL + pgvector:* Fast, mature 384-dimensional cosine similarity search on consideration embeddings via HNSW index.
  - *Neo4j AuraDB:* Deep multi-hop relational graph capturing trial metadata, country-specific patterns, and Louvain community clusters.
  - *The Bridge:* Shared join key `consideration_id` in format `{rfi_id}-C{number}` guarantees zero data drift between relational and graph databases.
- **Right Panel (The Retrieve-Then-Enrich Query Flow):**
  - Safety screen → Vector search (pgvector) → Structural graph enrichment (Neo4j) → Outcome re-ranking (60% semantic + 40% success score) → OPA policy authorization.

#### 🎙️ Word-for-Word Speaker Script
> "Architecturally, ClarION solves a common enterprise failure mode: trying to force one database to do everything.
> 
> Vector databases alone lack relational awareness; graph databases alone can be slow and brittle for vector search. ClarION uses a state-of-the-art **Retrieve-Then-Enrich** design.
> 
> When a regulatory specialist queries ClarION, PostgreSQL with pgvector executes sub-millisecond semantic search across thousands of historical considerations. Then, Neo4j enriches the retrieved records with multi-hop context: which country raised it, which CTR article was referenced, and whether it belongs to a recurring pattern.
> 
> Both databases share a canonical join key—`consideration_id`—ensuring zero data drift and 100% audit consistency across systems."
